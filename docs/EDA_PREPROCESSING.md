# EDA & Preprocessing Record

> Required by CLAUDE.md §6. This document summarizes the exploratory data analysis and preprocessing steps applied to the Base_de_Dados acoustic fault dataset.

## Zero-crossing rate correction — 2026-09-09

The old EDA and baseline extractors used `np.diff(np.sign(audio) != 0)`.
That detects transitions between zero and nonzero samples rather than changes
between negative and positive amplitudes. Both extractors now share
`src.signal_statistics.zero_crossing_rate`.

The corrected statistic is the count of transitions between negative and
nonnegative samples divided by `N - 1`. Both signed zeros are nonnegative;
there is no amplitude threshold or sample-rate conversion. The standalone
statistic returns 0 for fewer than two samples and rejects non-finite,
non-real, or non-mono inputs. It fits no state and leaves the input unchanged.
The feature count/order is preserved: ZCR is index 12 in the 25-feature EDA
vector and index 13 in the 24-feature baseline vector (zero-based).

**Existing results are historical, not regenerated by this code fix.** The ZCR
columns in `results/eda_features_summary.csv` and the PCA/t-SNE figure derived
from the full feature vector need regeneration. Any classical model trained on
the old features needs retraining with corrected features on the same approved
training split; feeding corrected features to an old fitted model is not a
valid comparison. Perform development EDA/scaling on training data and tuning
on validation data. Do not automatically rerun the previously inspected test
set as part of this repair. Keep original reports for provenance.

The waveform/PSD examples and the RMS, kurtosis, crest-factor, and centroid
boxplots do not use ZCR. TF-FaultNet's log-Mel extractor and CNN also do not
consume this statistic, so this correction does not alter their weights or
invalidate their predictions on account of ZCR.

Validation: 14 tests passed (seven statistic tests, three isolated extractor
tests, and four frozen-manifest tests). The original source returned 0 for
`[-1, 1, -1, 1]`; the corrected source returns 1. A smoke check on one training
recording from each macro class matched independent scalar crossing counts;
all non-ZCR features matched the old implementation exactly.

Windows Application Control blocked PyTorch's `c10.dll`, including outside the
sandbox, so full module-import integration was not verified. The extractor
tests compile the actual numerical function bodies and shared-statistic import
from source using real NumPy/SciPy, without importing the model or plotting
dependencies. This is explicitly isolated arithmetic coverage, not a successful
end-to-end training/EDA run. Syntax compilation also passed.

Run from the project root in an environment with NumPy and SciPy installed:

```powershell
.\.venv-roc\Scripts\python.exe -m unittest discover -s tests -v
```

## 6. Outliers / Anomalies

- No signal-level outliers detected (all amplitudes in normalized [-1.0, 1.0] range).
- Crest factor and kurtosis vary significantly across fault types, which is expected and informative.
- No samples removed for outlier reasons (CLAUDE.md §3.7: "Do not remove outliers only to improve metrics").

---

## 7. Class Imbalance

- **Severe for 3-class:** Class 0 has 179 samples vs 1,074 for Class 1.
- **Mitigation:** Stratified splitting ensures proportional representation in train/val/test. Macro F1 is the primary metric to avoid accuracy being dominated by the majority class. Label smoothing (ε=0.05) provides minor regularization.

---

## 8. Correlated Features

- Time-domain features (RMS, peak, energy) are moderately correlated.
- Frequency-domain features (spectral centroid, bandwidth, rolloff) form a second correlated cluster.
- The deep model (TF-FaultNet) performs automatic feature extraction from raw audio, bypassing manual feature selection.

## 9. Group / Session / Site Structure

| Factor | Status |
|--------|--------|
| **Site** | Single laboratory test rig (single-site) |
| **Subject/Object** | Single belt-drive system |

- Each WAV file is an independent 1-second snapshot.
- No temporal sequence exists across files (they are IID within each condition).
- A random stratified split is appropriate (chronological split not needed).

## Preprocessing Pipeline

| Step | Operation | Applied To |
|------|-----------|-----------|
| 1 | Load 16-bit PCM WAV → float32 [-1.0, 1.0] | All data |
| 2 | Pad/trim to 44,100 samples | All data |
| 3 | Log-Mel spectrogram extraction | Inside model (end-to-end) |
| 4 | Per-spectrogram normalization (zero-mean, unit-variance) | Inside model |
| 5 | Random noise augmentation (σ=0.003, p=0.35) | **Train only** |
| 6 | Random gain augmentation (0.85–1.15×, p=0.35) | **Train only** |

> All stateful transformations (spectrogram normalization parameters) are computed per-sample, not fit on training data globally. Augmentation is applied to the training set only.

Training and baseline scripts read assignments from the frozen
`data/splits.csv::split_multiclass_3class` column. They do not generate a new
partition at runtime.
